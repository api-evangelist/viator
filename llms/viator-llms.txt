# Viator

> Viator is a Tripadvisor company and the largest online marketplace for tours, activities and travel experiences, listing more than 300,000 bookable products across roughly 2,500 destinations. It sits on the demand side of travel distribution as an aggregator and reseller of third-party operator inventory, and on the supply side as the channel counterparty that tour operators' reservation systems connect into. Its developer surface is unusually open for travel: four complete OpenAPI documents and four Postman collections are downloadable without a login, and Basic Access affiliate keys are issued self-serve at no cost.

Generated by API Evangelist on 2026-07-28. Viator does not publish an llms.txt of its own — /llms.txt returns 403 on docs.viator.com and 404 on partnerresources.viator.com — so this file is generated from apis.yml and the artifacts in this repository.

Key facts an agent should know before calling anything:

- Authentication is a single organisation-wide API key sent in the `exp-api-key` header. There is no OAuth, no scopes and no per-user delegation, so every call carries the full authority of the partner account.
- `Accept: application/json;version=2.0` is mandatory on every Partner API v2 request. Omitting it returns HTTP 400 `INVALID_HEADER_VALUE`.
- Endpoint access is gated by partner tier (Basic-access Affiliate, Full-access Affiliate, Full-access + Booking Affiliate, Merchant), not by scope. An out-of-tier call returns 403.
- `partnerBookingRef` is the idempotency key for booking creation. Retry with the same value; Viator enforces its uniqueness so a duplicate booking cannot be created.
- All testing must happen on `https://api.sandbox.viator.com/partner`. Production is for live bookings only.
- Product reviews and everything inside `viatorUniqueContent` are licensed content that must not be exposed where a search engine can index it.
- No open travel standard (OpenTravel/OTA, HTNG, NDC, IATA) is referenced anywhere in any Viator specification.

## APIs

- [Viator Partner API v2](https://docs.viator.com/partner-api/technical/): The current demand-side contract — products, availability, bookings, payments, attractions and auxiliary reference data. OpenAPI 3.0.2, 33 operations, licensed CC BY 4.0. Base URL `https://api.viator.com/partner`.
- [Viator Reservation System API](https://docs.viator.com/supplier-api/technical/): The supplier-side connectivity contract, formerly the Supplier API. Inverted — it defines the endpoints a tour operator's reservation system must itself implement for Viator to call. OpenAPI 3.0.0, 15 operations, with published uptime, latency and error-rate SLAs and Viator-operated circuit breakers.
- [Viator Merchant API v1](https://docs.viator.com/partner-api/merchant/technical/): Legacy v1 merchant contract, superseded by the Partner API v2 but still published. OpenAPI 3.0.1, 28 operations.
- [Viator Affiliate API v1](https://docs.viator.com/partner-api/affiliate/technical/): Legacy v1 non-transactional affiliate contract, superseded by the Partner API v2. OpenAPI 3.0.2, 20 operations.
